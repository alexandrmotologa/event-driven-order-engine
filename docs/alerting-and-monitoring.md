# Declarative Alerting, Incident Management & Observability Guide

## 1. System Architecture & Observability Topology

The **Event-Driven Order Processing & Workflow Engine** implements an enterprise-grade observability and alerting pipeline combining **Prometheus**, **Alertmanager**, and **Grafana**:

```
 ┌─────────────────────────────────────────────────────────────┐
 │       Order Processing Engine (Spring Boot 3.3 / Java 21)   │
 │   - Micrometer Prometheus Meter Registry                     │
 │   - OpenTelemetry W3C Tracing                                │
 │   - Resilience4j Circuit Breaker & Rate Limiter Telemetry   │
 └──────────────────────────────┬──────────────────────────────┘
                                │ Polls /actuator/prometheus (every 5s)
                                ▼
 ┌─────────────────────────────────────────────────────────────┐
 │                     Prometheus (Port 9090)                  │
 │   - Stores Time-Series Metrics                              │
 │   - Evaluates PromQL Rules in alert-rules.yml (every 5s)   │
 └──────────────────────────────┬──────────────────────────────┘
                                │ Dispatches firing alerts
                                ▼
 ┌─────────────────────────────────────────────────────────────┐
 │                    Alertmanager (Port 9093)                 │
 │   - Groups alerts by severity & team                        │
 │   - Suppresses cascades via Inhibition Rules                │
 │   - Dispatches Webhooks (Slack, Discord, PagerDuty)         │
 └─────────────────────────────────────────────────────────────┘
```

## 2. Declarative Alert Rules Catalog (`docker/prometheus/alert-rules.yml`)

All alerting rules are declarative, version-controlled, and continuously evaluated against live engine metrics:

| Alert Name | Severity | Trigger Expression | Evaluation Window | Business Impact / Mitigation |
| :--- | :--- | :--- | :--- | :--- |
| **`HighSagaFailureRate`** | `CRITICAL` | `rate(orders_saga_failures_total[2m]) > 0.05` | `1m` | Distributed transaction compensations exceed 5%. Investigate downstream inventory/payment service health. |
| **`SagaTimeoutDetected`** | `WARNING` | `increase(orders_saga_timeout_total[1m]) > 0` | `30s` | Dead-Man Switch triggered due to participant silence (> 30s). Verify Kafka broker connectivity and consumer worker threads. |
| **`DlqPoisonPillAccumulation`**| `CRITICAL` | `orders_dlq_pending_count > 0` | `1m` | Poison pill messages captured in `order.events.dlq`. Inspect via `/api/v1/dlq/messages` and trigger redrive or patch. |
| **`PaymentCircuitBreakerOpen`**| `CRITICAL` | `resilience4j_circuitbreaker_state{name="paymentService",state="open"} == 1` | `15s` | Payment gateway failure rate exceeded threshold. Fallback active; escalate to payment provider support. |
| **`HighRateLimitRejectionRate`**| `WARNING` | `rate(orders_ratelimit_rejected_total[1m]) > 5` | `30s` | Surge in HTTP 429 rejections. Tenant traffic exceeds quotas; check for runaway scripts or potential DDoS attacks. |

## 3. Alert Routing & Inhibition Rules (`docker/alertmanager/alertmanager.yml`)

### Grouping & Throttling
Alertmanager groups alerts by `alertname`, `severity`, and `team`:
- `group_wait: 10s`: Initial buffering to prevent alert storms during widespread outages.
- `group_interval: 1m`: Frequency of new notifications for newly firing alerts in an active group.
- `repeat_interval: 4h`: Deduplicates active alerts, preventing alert fatigue.

### Cascade Inhibition
When a `critical` alert (such as `PaymentCircuitBreakerOpen`) fires, Alertmanager automatically mutes lower-priority `warning` alerts generated by the same team, focusing operations on the root cause.

## 4. Operational Playbook & Verification

### Running the Observability Stack
Start the Prometheus, Alertmanager, Grafana, and Jaeger stack:
```bash
docker-compose up -d prometheus alertmanager grafana jaeger
```

### Accessing Dashboards
- **Prometheus UI**: [http://localhost:9090](http://localhost:9090) (navigate to Status ➔ Rules or Alerts)
- **Alertmanager UI**: [http://localhost:9093](http://localhost:9093)
- **Grafana Live Dashboard**: [http://localhost:3000](http://localhost:3000) (admin / admin)
- **Application Metrics Endpoint**: [http://localhost:8080/actuator/prometheus](http://localhost:8080/actuator/prometheus)

### Simulating an Incident & Firing Alerts
1. Open the interactive control panel at [http://localhost:8080/dashboard](http://localhost:8080/dashboard).
2. Under **Chaos Engineering**, check **Simulate 503 Payment Gateway Outage** and click **Apply Faults**.
3. Fire 5 simulated orders. The external payment gateway will reject requests, tripping the Circuit Breaker to `OPEN`.
4. Open [http://localhost:9090/alerts](http://localhost:9090/alerts) to observe `PaymentCircuitBreakerOpen` transitioning from `PENDING` to `FIRING`.
5. Reset chaos using **Reset Healthy**; the alert resolves automatically within 15 seconds.
